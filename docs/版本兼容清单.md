# 版本兼容清单

显示版本（`view_sessions.ui_version`）、渲染对象来源版本
（`rendered_objects.source_version`）与路线意图版本
（`view_sessions.route_intent_version`）是三套独立版本号。**不能按字符串
前缀或数字大小猜测对应关系**；只有在本清单显式登记的组合，才允许判断
"用户看见的内容与当时计划一致"。

## 已登记的对齐组合

| 显示版本 | 对象来源版本 | 可对齐的路线意图版本 |
| --- | --- | --- |
| UI-A | UI-0 | NAV-0、NAV-2 |
| UI-A | UI-1 | NAV-0、NAV-2 |
| UI-B | UI-1 | NAV-1、NAV-3 |
| UI-B | UI-2 | NAV-1、NAV-3 |

代码中的唯一事实来源是 `domain.VERSION_ALIGNMENT`；本文件是其人工可读
镜像，修改时两处必须同步并在 `config_epochs` 登记配置纪元。

## 判定规则

1. 会话的每个非孤儿渲染对象都必须落在已登记组合内，会话才算版本对齐；
2. 任一对象来源版本未登记，整个会话判为版本错配，可观察程度降为
   **L3-关联缺口**，不允许据此解释理解度；
3. 没有任何可关联渲染对象的会话同样进入 L3；
4. 兼容清单只追加、不回改。历史会话固定使用其导入时记录的版本，
   后续清单调整不重新解释历史证据（见 `docs/运行说明.md` 的"版本封存"）。

## 基线资料的实际情况

仓库基线 `data/` 是混合场景：50 个会话中 33 个命中上表组合，17 个
（UI-A 配 UI-2、UI-B 配 UI-0 等）未登记而降级 L3。这正说明不能凭
版本号外观判断一致性。
