# 运行说明（中文）

适用 Python 3.11–3.14，仅使用标准库，无需第三方依赖。所有数据均为本地
虚构合成资料，不包含真实驾驶员、车辆或道路信息。

## 1. 环境准备

```sh
python3 -m venv .venv
. .venv/bin/activate          # Windows PowerShell 用 .venv\Scripts\Activate.ps1
pip install -e .
```

安装后得到命令 `reality-view`，也可以用 `python -I -m reality_view_comprehension`
调用（`-I` 为隔离模式，忽略当前目录，防止资料目录中的同名模块被导入）。

## 2. 一分钟端到端演示

```sh
python -I -m reality_view_comprehension demo --workdir work/demo
```

演示依次完成：生成合成数据 → 首批导入 → 晚到批次幂等再导入 → 理解度
分析与报告导出 → 开放决策 → 设备/路线/授权/任务/配置纪元维护。
重复运行需加 `--force`。

## 3. 分步命令

### 3.1 导入曝光与研究结果（可重复、可持续）

```sh
python -I -m reality_view_comprehension import --db work/rvc.db --data-dir data
```

- 同一数据库可多次导入：同主键记录跳过并登记到 `import_conflicts`，
  已导入的显示/意图版本不会被覆盖；
- 非法行进入 `quarantine_rows`，有效行正常入库；
- 每次导入全量重算孤儿对象与误触标记，与导入顺序、晚到曝光无关；
- 晚到资料放进单独目录再导入即可（合成器的 `late/` 目录即此模式）。

### 3.2 分析理解度边界

```sh
python -I -m reality_view_comprehension analyze --db work/rvc.db --out work/report
```

导出五件产物：

| 文件 | 内容 |
| --- | --- |
| `理解度分析报告.md` | 中文报告：覆盖边界、三维分层、版本汇总、缺口、口径 |
| `group_metrics.csv` | 显示版本 × 任务类型 × 可观察程度 指标 |
| `ui_rollups.csv` | 显示版本 × 可观察程度 跨任务汇总 |
| `session_evidence.csv` | 每个会话的证据明细与分级（含版本、误触、问卷状态） |
| `analysis_report.json` | 机器可读的完整报告 |

### 3.3 开放决策与试用名单

```sh
python -I -m reality_view_comprehension decide --db work/rvc.db
python -I -m reality_view_comprehension decide --db work/rvc.db --json
```

输出 `hold_rollout / follow_up_study / restricted_trial` 建议（每条带
证据回链）以及每位驾驶员的早期试用资格与原因。门槛可用参数覆盖，例如：

```sh
python -I -m reality_view_comprehension decide --db work/rvc.db \
  --min-l1-sessions 10 --min-comprehension-rate 0.8
```

### 3.4 研究/试行计划维护

```sh
# 运营资源
python -I -m reality_view_comprehension plan-device  --db work/rvc.db --device-id DEV-1 --model rig-A
python -I -m reality_view_comprehension plan-route   --db work/rvc.db --route-id RT-1 --name 合成转弯路线 --task-type turn --ui-version UI-B
python -I -m reality_view_comprehension plan-grant   --db work/rvc.db --driver-key D-01 --scope sim-trial
python -I -m reality_view_comprehension plan-withdraw --db work/rvc.db --driver-key D-01 --note 参与者退出

# 任务生命周期（planned -> scheduled -> active -> completed；另有 cancelled/superseded）
python -I -m reality_view_comprehension plan-create     --db work/rvc.db --task-id T-1 \
    --ui-version UI-B --intent-version NAV-1 --task-type turn --route-id RT-1 --device-id DEV-1 --driver-key D-01
python -I -m reality_view_comprehension plan-transition --db work/rvc.db --task-id T-1 --status scheduled
python -I -m reality_view_comprehension plan-transition --db work/rvc.db --task-id T-1 --status active
python -I -m reality_view_comprehension plan-transition --db work/rvc.db --task-id T-1 --status completed

# 界面配置变化：登记新纪元，未完成且版本不匹配的任务置 superseded
python -I -m reality_view_comprehension plan-epoch --db work/rvc.db --epoch-id EPOCH-2 --ui-version UI-C --note 界面升级
python -I -m reality_view_comprehension plan-list --db work/rvc.db
```

规则违反（终态任务再迁移、撤回授权后建任务、路线与显示版本不一致等）
会以退出码 2 和中文提示被拒绝，不产生脏数据。

### 3.5 生成合成数据

```sh
python -I -m reality_view_comprehension synthetic --out work/synthetic --seed 20261124 --n-sessions 30
```

固定种子逐字节可复现，输出 `baseline/`（含误触、孤儿、错配、撤回、
非法行等边界）与 `late/`（晚到批次）。加 `--no-edge-cases` 可生成
不含边界样例的干净资料。

## 4. 版本封存（配置变化后的硬约束）

1. 计划开始后的界面配置变化只能通过 `plan-epoch` 追加新纪元；
2. 受影响的未完成任务变为 `superseded`，不再适用；
3. 已完成任务在完成瞬间把显示/意图版本冻结到
   `frozen_ui_version / frozen_intent_version`，状态进入终态不可改；
4. `view_sessions` 与 `study_responses` 没有任何更新路径，重复导入
   同主键只会在 `import_conflicts` 登记，分析始终按会话自身版本解释。

## 5. 运行测试

```sh
python -I -m unittest discover -s tests -v
```

- `tests/test_materials.py`：基线资料契约（原有）；
- `tests/test_pipeline.py`：合成数据可复现性、导入隔离/幂等、分级
  不变量、分层分析、决策回链、计划状态机与版本封存（20 个用例）。

## 6. 数据库表速览

| 表 | 用途 |
| --- | --- |
| `view_sessions / rendered_objects / interactions / study_responses` | 四类原始资料（带孤儿、误触标记） |
| `quarantine_rows` | 未通过校验的隔离行及原因 |
| `import_runs / import_conflicts` | 导入批次与幂等冲突审计 |
| `config_epochs` | 界面配置纪元（只追加） |
| `devices / simulated_routes / participant_authorizations` | 运营资源与授权 |
| `study_tasks / task_events` | 任务状态机与事件流水 |
